# EES/MES 데이터 모델 재설계

**작성일** 2026-07-29
**상태** 구현 완료. 단, 조인 방향은 같은 날 한 번 뒤집혔다 — 규칙 1 아래의
정정 상자를 먼저 읽을 것.
**범위** 금형 수집 파이프라인의 소스 정의와 불량율 조인. 대시보드 화면은 건드리지 않는다.

## 무엇이 바뀌는가

지금까지 `MES` 폴더의 파일 하나가 금형 목록·상태·불량율을 전부 declare 했다.
실물은 그렇지 않다. 소스가 셋으로 갈라지고, **어느 것도 혼자서는 금형 하나의
불량율을 말할 수 없다.**

| 소스 | 폴더 | 무엇을 아는가 | 무엇을 모르는가 |
|---|---|---|---|
| JIG 관리대장 | `EES/` | **JIG ID**, 설비명, 언제 설비에 들어가고 나왔는지 | 생산 실적을 모른다 |
| JIG 기준정보 | `JIG기준정보/` | 금형번호 ↔ 설비명 ↔ 설비코드 ↔ 라인 | 시간 정보가 없다 |
| MES | `MES/` | 날짜·라인·설비코드별 생산/불량 수량 | **금형번호를 모른다** |

MES 는 금형번호를 모른다. 기준정보가 그 사이에서 조회 키(설비코드)를 내주는
유일한 다리다 — 빠지면 불량율이 통째로 비어 버린다.

## 조인 사슬

```
JIG관리대장 (한 시트에 여러 금형)      JIG기준정보              MES (하루 한 파일)
  JIG ID ─────────────────────────→ 금형 확정
  설비명 ──────────→ 기준정보[설비명] ─┐
                        (없으면 폴백)   ├─ 설비코드 ──→ 설비코드
  JIG ID ──────────→ 기준정보[JIG ID] ─┘  + Line명     + 날짜
  위치 "설비" 진입~이탈 = 사용구간 ──────────────────→ 날짜
```

라인 문자열을 패턴으로 뜯지 않는다. 관리대장의 라인(`Pouch #10(S)`)과 기준정보의
Line명(`톈진 Pouch #10(S)`)은 실제로 다르다 — 공장 접두사가 붙고 안 붙고의 차이다.
문자열끼리 비교하면 조용히 안 맞는다. **MES 조회는 설비코드로만 한다.**

## 규칙 넷

### 1. 사용구간 추출 (관리대장)

**JIG ID 로 묶어서** 이벤트를 시간순으로 정렬하고:

- `위치 == "설비"` 인 이벤트 = **투입**
- 바로 다음 이벤트의 시각 = **종료** (그 이벤트의 위치가 무엇이든 상관없다)
- 마지막 이벤트가 `설비` 면 아직 가동 중 — 종료 없음, 불량율 조인도 없음

한 시트에 여러 금형의 이벤트가 섞여 있으므로 시트로 묶으면 A 금형의 설비 진입이
B 금형의 다음 이벤트로 닫힌다. 파일 경계도 넘어 묶는다 — 금형 이력은 파일이
아니라 금형을 따라 이어진다. 대신 관리대장이 겹쳐 올라올 때를 대비해 완전히
같은 이벤트(JIG ID·시각·위치·설비명이 모두 같음)는 하나로 접는다.

> **2026-07-29 정정.** 이 문서의 초판은 "시트 하나가 금형 하나이고, 금형을
> 확정하는 것은 설비명 열이다(시트 이름은 사람이 바꾸거나 겹칠 수 있어 못
> 믿는다)"고 적었다. **전제가 틀렸다.** JIG ID 는 시트 이름이 아니라 **행마다
> 있는 열**이고, 이미 알고 있는 안정된 키다. 설비명으로 금형을 식별하면 (a)
> 기준정보에 설비가 빠진 순간 금형이 통째로 사라지고 (b) 사람이 고칠 수 있는
> 문자열이 금형 정체성을 좌우한다. 그래서 방향을 뒤집었다.

### 2. 금형 식별 (관리대장의 JIG ID)

행의 `JIG ID` 가 그 행의 금형을 확정한다. `#RX39513` 의 `#` 는 기존
`normalize_mold_no` 가 이미 떼므로 IQC 대장의 `RX39513` 과 자동으로 합쳐진다.

그 JIG ID 로 기준정보를 조회해 설비코드·Line명을 얻는다. **기준정보에 없는
JIG ID 는 금형을 만들지 않는다** — 조회 키가 없어 불량율을 붙일 수 없기 때문이다.
조용히 버리지 말고 건수를 집계해 드러낸다.

### 2-1. 조회 키 선택 (설비명은 식별이 아니다)

구간마다 MES 조회에 쓸 설비코드는 **그 이벤트의 설비명**으로 고른다. 기준정보에
없는 설비명이면 JIG ID 행으로 폴백한다.

| 경우 | 조회 키 | 손실 |
|---|---|---|
| 설비명이 기준정보에 있음 | 그 설비의 설비코드·Line명 | 없음 |
| 설비명이 기준정보에 없음 | JIG ID 행의 설비코드·Line명 | 경고(금형은 남는다) |
| JIG ID 가 기준정보에 없음 | 없음 — 금형을 만들지 않는다 | 치명 |

식별(JIG ID)과 조회(설비명)를 나누는 이유: 금형이 설비를 옮겨 다녀도 각 구간이
**그때 그 설비**의 실적에 붙는다. 기준정보는 JIG ID 당 현재 설비 하나만 알기
때문에, 그것으로 고정하면 과거 구간에 남의 실적이 붙는다.

### 3. 대조할 날짜 (사용구간 → 날짜 목록)

투입 시각부터 24시간 단위로 끊는다. `올림(사용시간 ÷ 24h)` 일수만큼 투입일부터 센다.

| 사용구간 | 시간 | 날짜 |
|---|---|---|
| 07-01 07:00 ~ 07-05 07:00 | 96.0h | 07-01, 02, 03, 04 |
| 07-02 08:30 ~ 07-03 09:00 | 24.5h | 07-02, 07-03 |
| 07-08 06:00 ~ 07-08 18:00 | 12.0h | 07-08 |
| 07-10 22:00 ~ 07-12 03:00 | 29.0h | 07-10, 07-11 |

96시간이 정확히 4일이고 07-05 가 **안** 들어가는 것이 이 규칙의 경계다.

### 4. 불량율 집계 (MES)

날짜별로 `(라인, 설비코드)` 가 맞는 행을 찾아 **raw 수량을 합친 뒤 다시 계산**한다.

```
불량율(PPM) = Σ불량수량 ÷ Σ투입수량 × 1,000,000
```

비율의 평균이 아니다. 생산량이 다른 날을 같은 무게로 세면 틀린 값이 나온다.
샘플에서 실제로 갈린다 — RX39513 의 일별 PPM 평균은 11,003 이고 raw 합산
재계산은 **11,269** 다.

`TOTAL` 행은 라인이 아니므로 조인에서 제외한다.

## 드러내야 할 손실

이 파이프라인의 기존 원칙("조용한 손실 금지")을 그대로 따른다. `RunSummary` 에
아래를 더한다.

| 항목 | 언제 | 왜 화면에 떠야 하는가 |
|---|---|---|
| 기준정보에 없는 **JIG ID** | 관리대장에 있는데 매핑 없음 | 그 금형이 통째로 안 나온다 |
| 기준정보에 없는 **설비명** | 그 설비가 매핑에 없음 | 금형은 나오되 실적이 *현재 설비* 기준이다 |
| MES 파일이 없는 날짜 | 사용구간이 덮는 날의 파일 부재 | 불량율이 일부 날만 반영된다 |
| MES 에서 못 찾은 (라인, 설비코드) | 파일은 있는데 행이 없음 | 라인 표기가 어긋났다는 신호 |
| JIG ID 를 못 읽은 행 | 관리대장 행에 값이 없음 | 어느 금형에도 못 붙는다(`skipped_rows` 에 합산) |
| 종료 없는 사용구간 | 아직 설비에 있음 | 손실이 아니라 정상 — 구분해서 보여야 한다 |

앞의 두 항목이 **같은 무게로 읽히면 안 된다.** JIG ID 가 없으면 금형이 사라지고,
설비명이 없으면 금형은 남되 값의 근거가 달라진다 — 사용자가 할 일이 다르다.

마지막 항목도 중요하다. "불량율 없음"이 **가동 중이라 아직 없는 것**인지
**조인이 깨진 것**인지 구분되지 않으면 사람이 판단할 수 없다.

## 저장 위치

`db.py` 의 `production_run` 이 이미 이 모양이다 — `mold_no, install_seq, line,
machine, started_at, ended_at, defect_rate, defects_json`. 지금은 비어 있다.

사용구간 한 건 = `production_run` 한 행. `defect_rate` 에 합산 결과를,
`defects_json` 에 날짜별 원값을 남겨 근거를 되짚게 한다. `mold.latest_defect_rate`
는 가장 최근 구간의 값이다. `machine` 열에는 **그 구간의 설비명**이 들어간다 —
금형이 옮겨 다녔다면 구간마다 다르다.

> 초판에서 미승인으로 남겼던 항목이다(대안: 금형당 최신값만 갱신 / `mold_stage`
> 에 'mes' 단계로 부착). 위 (a) 안으로 구현했다.

## 확정되지 않은 것: MES 양식

사용자가 준 MES 컬럼에는 **설비코드도, 양품수/불량수도 없었다.**

```
공장, 대표라인, 라인,
종합/이탈율(PPM), 종합/불량율(PPM), 종합/Loss율(PPM), 종합/재작업율(%),
조립라인/…, 조립별화성/…
```

그런데 조회 키가 `(날짜, 라인, 설비코드)` 이고 집계가 raw 수량 합산이므로 둘 다
있어야 한다. 없으면 비율의 단순 평균밖에 못 하는데 그것은 위에서 기각한 방법이다.

샘플에는 `설비코드`, `설비명`, `투입수량`, `양품수량`, `불량수량` 을 넣어 만들었다.
불량율(PPM)은 지어내지 않고 `불량수량 ÷ 투입수량 × 1,000,000` 으로 계산해 넣어,
합산 결과와 대조할 수 있게 했다. **실물 MES 를 받으면 이 부분만 고치면 된다.**

## 코드에 미치는 파급

| 파일 | 무엇이 바뀌었나 |
|---|---|
| `schemas.py` | `SourceKind` 에 `ees`/`jig_master`. `EES_FIELDS` 의 첫 필드가 `mold_no`(JIG ID). `JigInfo.equipment` 는 선택. `RunSummary.unknown_jig_id` 신설 |
| `discover.py` | `FIELD_GUIDE` 에 종류별 어휘. EES 는 JIG ID 열을 **필수**로 지목한다 |
| `pipeline.py` | `_PROCESSED_KINDS` 확대. 기준정보를 **먼저** 읽어야 한다(다른 둘의 해석에 필요) |
| `assemble.py` | 마스터가 MES → EES(관리대장+기준정보). 색인 두 벌(JIG ID·설비명) 사용 |
| `join.py` (신설) | 사용구간 추출·날짜 계산·MES 조인. 전부 순수 함수 |
| `store.py` | `production_run` 을 실제로 채운다 |
| `db.py` / `registry.py` | `ingest_run` 에 손실 컬럼(`unknown_jig_id_json` 등) |
| `.env.example` | `INGEST_STAGE_DIRS=EES:ees,JIG기준정보:jig_master,MES:mes,IQC:iqc,…` |

`join.py` 를 새 모듈로 두는 이유: 사용구간 추출과 날짜 계산은 Excel 도 LLM 도 DB 도
모르는 순수 계산이다. `normalize.py`·`layout.py` 와 같은 성격이라 격자 리터럴만으로
전부 테스트된다. 2단계의 PQC 조인도 같은 자리에 붙는다.

**설정 순서 주의**: `INGEST_STAGE_DIRS` 를 먼저 바꾸면 `SourceKind` 에 없는 종류가
생겨 스캐너가 깨진다. 코드와 함께 바꿔야 한다.

```
backend/data/uploads/

  JIG기준정보/JIG_기준정보.xlsx   6행

  PQC/2026-07_공정불량.xlsx       (기존 유지)
```

일부러 넣은 경계 조건은 `examples/make_sample_uploads.py` 의 docstring 에 적혀 있다.
`examples/check_samples.py` 가 **LLM 없이** 같은 규칙으로 기대값을 계산하므로,
수집 결과가 그것과 다르면 원인이 파이프라인인지 레이아웃 발견인지 구분할 수 있다.
