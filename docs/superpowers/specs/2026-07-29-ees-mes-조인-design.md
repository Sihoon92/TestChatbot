# EES/MES 데이터 모델 재설계

**작성일** 2026-07-29
**상태** 설계 승인 대기
**범위** 금형 수집 파이프라인의 소스 정의와 불량율 조인. 대시보드 화면은 건드리지 않는다.

## 무엇이 바뀌는가

지금까지 `MES` 폴더의 파일 하나가 금형 목록·상태·불량율을 전부 declare 했다.
실물은 그렇지 않다. 소스가 셋으로 갈라지고, **어느 것도 혼자서는 금형 하나의
불량율을 말할 수 없다.**

| 소스 | 폴더 | 무엇을 아는가 | 무엇을 모르는가 |
|---|---|---|---|
| JIG 관리대장 | `EES/` | 설비명, 언제 설비에 들어가고 나왔는지 | **금형번호를 모른다** |
| JIG 기준정보 | `JIG기준정보/` | 설비명 ↔ 금형번호 ↔ 설비코드 ↔ 라인 | 시간 정보가 없다 |
| MES | `MES/` | 날짜·라인·설비코드별 생산/불량 수량 | **금형번호를 모른다** |

기준정보가 두 조인의 유일한 다리다. 빠지면 금형 식별과 MES 조회가 **동시에**
끊긴다 — 부분 실패가 아니라 전면 실패다.

## 조인 사슬

```
JIG관리대장 (시트 = 금형 하나)        JIG기준정보                 MES (하루 한 파일)
  설비명 ────────────────────────┬── 설비명
  위치 "설비" 진입~이탈 = 사용구간  ├── JIG ID   → 금형번호
                                  ├── 설비코드 ──┬─→ 설비코드
                                  └── Line명 ────┴─→ 라인   + 날짜
```

라인 문자열을 패턴으로 뜯지 않는다. 관리대장의 라인(`Pouch #10(S)`)과 기준정보의
Line명(`톈진 Pouch #10(S)`)은 실제로 다르다 — 공장 접두사가 붙고 안 붙고의 차이다.
문자열끼리 비교하면 조용히 안 맞는다. **조인은 설비명으로만 한다.**

## 규칙 넷

### 1. 사용구간 추출 (관리대장)

시트 하나가 금형 하나다. 이벤트를 시간순으로 정렬하고:

- `위치 == "설비"` 인 이벤트 = **투입**
- 바로 다음 이벤트의 시각 = **종료** (그 이벤트의 위치가 무엇이든 상관없다)
- 마지막 이벤트가 `설비` 면 아직 가동 중 — 종료 없음, 불량율 조인도 없음

시트 이름은 금형 명칭이지만 금형을 확정하는 것은 **설비명 열**이다. 이름은
겹칠 수 있고 사람이 고칠 수도 있다.

### 2. 금형 식별 (기준정보)

관리대장의 설비명으로 기준정보를 찾아 `JIG ID` 를 얻는다. `#RX39513` 의 `#` 는
기존 `normalize_mold_no` 가 이미 떼므로 IQC 대장의 `RX39513` 과 자동으로 합쳐진다.

기준정보에 없는 설비명은 **금형을 만들지 않는다.** 조용히 버리지 말고 건수를
집계해 드러낸다.

### 3. 대조할 날짜 (사용구간 → 날짜 목록)

투입 시각부터 24시간 단위로 끊는다. `올림(사용시간 ÷ 24h)` 일수만큼 투입일부터 센다.

| 사용구간 | 시간 | 날짜 |
|---|---|---|
| 07-01 07:00 ~ 07-05 07:00 | 96.0h | 07-01, 02, 03, 04 |
| 07-02 08:30 ~ 07-03 09:00 | 24.5h | 07-02, 07-03 |
| 07-08 06:00 ~ 07-08 18:00 | 12.0h | 07-08 |
| 07-10 22:00 ~ 07-12 03:00 | 29.0h | 07-10, 07-11 |

96시간이 정확히 4일이고 07-05 가 **안** 들어가는 것이 이 규칙의 경계다.

### 4. 불량율 집계 (MES)

날짜별로 `(라인, 설비코드)` 가 맞는 행을 찾아 **raw 수량을 합친 뒤 다시 계산**한다.

```
불량율(PPM) = Σ불량수량 ÷ Σ투입수량 × 1,000,000
```

비율의 평균이 아니다. 생산량이 다른 날을 같은 무게로 세면 틀린 값이 나온다.
샘플에서 실제로 갈린다 — RX39513 의 일별 PPM 평균은 11,003 이고 raw 합산
재계산은 **11,269** 다.

`TOTAL` 행은 라인이 아니므로 조인에서 제외한다.

## 드러내야 할 손실

이 파이프라인의 기존 원칙("조용한 손실 금지")을 그대로 따른다. `RunSummary` 에
아래를 더한다.

| 항목 | 언제 | 왜 화면에 떠야 하는가 |
|---|---|---|
| 기준정보에 없는 설비명 | 관리대장에 있는데 매핑 없음 | 그 금형이 통째로 안 나온다 |
| MES 파일이 없는 날짜 | 사용구간이 덮는 날의 파일 부재 | 불량율이 일부 날만 반영된다 |
| MES 에서 못 찾은 (라인, 설비코드) | 파일은 있는데 행이 없음 | 라인 표기가 어긋났다는 신호 |
| 종료 없는 사용구간 | 아직 설비에 있음 | 손실이 아니라 정상 — 구분해서 보여야 한다 |

마지막 항목이 중요하다. "불량율 없음"이 **가동 중이라 아직 없는 것**인지
**조인이 깨진 것**인지 구분되지 않으면 사람이 판단할 수 없다.

## 저장 위치

`db.py` 의 `production_run` 이 이미 이 모양이다 — `mold_no, install_seq, line,
machine, started_at, ended_at, defect_rate, defects_json`. 지금은 비어 있다.

사용구간 한 건 = `production_run` 한 행. `defect_rate` 에 합산 결과를,
`defects_json` 에 날짜별 원값을 남겨 근거를 되짚게 한다. `mold.latest_defect_rate`
는 가장 최근 구간의 값이다.

> **미승인**: 사용자가 이 항목에 답하기 전에 양식을 다시 주었다. 착수 전 확인이
> 필요하다. 대안은 (b) 금형당 최신값만 갱신, (c) `mold_stage` 에 'mes' 단계로 부착.

## 확정되지 않은 것: MES 양식

사용자가 준 MES 컬럼에는 **설비코드도, 양품수/불량수도 없었다.**

```
공장, 대표라인, 라인,
종합/이탈율(PPM), 종합/불량율(PPM), 종합/Loss율(PPM), 종합/재작업율(%),
조립라인/…, 조립별화성/…
```

그런데 조회 키가 `(날짜, 라인, 설비코드)` 이고 집계가 raw 수량 합산이므로 둘 다
있어야 한다. 없으면 비율의 단순 평균밖에 못 하는데 그것은 위에서 기각한 방법이다.

샘플에는 `설비코드`, `설비명`, `투입수량`, `양품수량`, `불량수량` 을 넣어 만들었다.
불량율(PPM)은 지어내지 않고 `불량수량 ÷ 투입수량 × 1,000,000` 으로 계산해 넣어,
합산 결과와 대조할 수 있게 했다. **실물 MES 를 받으면 이 부분만 고치면 된다.**

## 코드에 미치는 파급 (아직 손대지 않음)

| 파일 | 무엇이 바뀌나 |
|---|---|
| `schemas.py` | `SourceKind` 에 `ees`/`jig_master` 추가. `MES_FIELDS` → `EES_FIELDS` + 새 `MES_FIELDS`. `ProductionRun` 모델 신설 |
| `discover.py` | `FIELD_GUIDE` 에 세 종류 어휘 추가 |
| `pipeline.py` | `_PROCESSED_KINDS` 확대. 기준정보를 **먼저** 읽어야 한다(다른 둘의 해석에 필요) |
| `assemble.py` | 마스터가 MES → EES(관리대장+기준정보) 로 바뀐다 |
| `join.py` (신설) | 사용구간 추출·날짜 계산·MES 조인. 전부 순수 함수 |
| `store.py` | `production_run` 을 실제로 채운다 |
| `.env.example` | `INGEST_STAGE_DIRS=EES:ees,JIG기준정보:jig_master,MES:mes,IQC:iqc,…` |

`join.py` 를 새 모듈로 두는 이유: 사용구간 추출과 날짜 계산은 Excel 도 LLM 도 DB 도
모르는 순수 계산이다. `normalize.py`·`layout.py` 와 같은 성격이라 격자 리터럴만으로
전부 테스트된다. 2단계의 PQC 조인도 같은 자리에 붙는다.

**설정을 아직 바꾸지 않은 이유**: `INGEST_STAGE_DIRS` 를 먼저 바꾸면 `SourceKind` 에
없는 종류가 생겨 스캐너가 깨진다. 코드와 함께 바꿔야 한다.
