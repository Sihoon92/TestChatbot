# 코팅 전처리 재정의 — 앵커 병합과 ±10분 격리

- 날짜: 2026-09-08
- 배경: 지금의 조정 이벤트 정의(연쇄 병합 2분 + 앞30/뒤60 격리)는 한 번의 조작과
  여러 번의 조작을 구별하지 못한다. 8분에 걸친 여섯 번의 손질이 "t₀ 에 일어난 한 번의
  계단 입력" 으로 읽히고, 그 상태로 격리를 통과해 L·τ 와 영향행렬에 들어간다.
  이 문서는 이벤트의 정의 자체를 바꾸고, 바뀐 전처리를 **사람이 눈으로 검증할 수 있는
  로그**를 함께 설계한다.
- 선행 문서:
  - `docs/superpowers/specs/2026-08-25-코팅-초기조건-도출-design.md` (전체 과제)
  - `docs/understanding/2026-09-07-01-explanation-coating-noise-floor.html` (가드 밴드)
  - `docs/measurements/2026-09-07-coating-48X1-kernel-diagnosis.md`
- 결정 경위: 브레인스토밍 3라운드. 세 갈림길(응답창 정합 / 선별 경로 통합 / 연속 조작 처리)에
  대한 결정과 근거는 마지막 절에 남긴다.

## 문제 — 지금 규칙의 결함 넷

### 1. 연쇄 병합이 "한 번의 조작" 을 정의하지 못한다

`events.py:30-32` 이 전부다.

```python
gap = ctrl.groupby(S.LOT)[S.AT].diff()          # 직전 "변경" 과의 간격
new_group = gap.isna() | (gap > pd.Timedelta(minutes=merge_minutes))
```

`diff()` 는 **직전 변경과의** 간격이지 묶음 시작점과의 간격이 아니다. 2분 이하로 이어지면
묶음이 무한히 이어붙는다(single-linkage). 합성 검증:

```
변경 시각(분): 0, 1.5, 3, 4.5, 6, 8, 120

[현재 = 연쇄 병합, merge=2]
lot_id event_id           worked_at  n_items
    L1     L1#1 2026-02-02 06:00:00        6     ← 8분짜리가 통째로 한 이벤트
    L1     L1#2 2026-02-02 08:00:00        1
event_id  gap_before  gap_after  isolated
    L1#1         NaN      120.0      True        ← 격리 통과
    L1#2       120.0        NaN      True
```

이 이벤트의 `worked_at` 은 첫 변경 시각 06:00 이다. 실제 입력은 8분에 걸쳐 들어갔는데
그 뒤 60분을 "06:00 계단 입력의 응답" 으로 읽는다. 순수지연 L 이 분 단위라면 8분
스미어링은 L 을 직접 오염시킨다.

### 2. 간격을 이벤트 **시작**에서 잰다

`events.py:248` — `gap_after = 다음 이벤트의 시작 − 이 이벤트의 시작`. 이벤트가 span 을
가지면 실제 조용한 시간은 그보다 span 만큼 짧다. 지금은 span 이 무제한이라 오차도 무제한이다.

### 3. "쓸 수 있는 이벤트" 정의가 둘로 갈라져 있다

| | 고르는 방법 | 쓰는 곳 |
|---|---|---|
| `annotate_settling` → `CONTAMINATED` | Wet 이 정착했나 (출력 기반, 순환) | `features.py:58` → 커널/영향행렬 |
| `isolation` → `isolated` | 앞뒤에 다른 조정이 있나 (시각만) | `report._dynamics_facts` → L·τ |

`report.py` 의 주석은 정착 기반이 순환이라 격리로 갈아탔다고 적혀 있는데, 커널 쪽은
여전히 `CONTAMINATED` 를 쓴다. 리포트가 내는 "쓸 수 있는 이벤트 N건" 이 절마다 다른 뜻이다.

### 4. 파생 버그 — 한 묶음 안에서 같은 zone 을 두 번 만지면 Δgap 이 깨진다

zone1 을 40→41→42→43 (총 +3) 으로 4분에 걸쳐 세 번 만진 경우, 연쇄 병합은 한 묶음으로
삼키고 `dl` 에 `(event, item)` 이 3중복으로 남는다.

```
event_id  item_id  zone  delta
    L1#1 30030838   1.0    1.0
    L1#1 30030838   1.0    1.0
    L1#1 30030838   1.0    1.0
```

`features.delta_samples` 가 이 행들을 루프로 **같은 칸에 덮어쓴다** → 최종
`Δgap[zone1] = +1`. 그런데 ΔWet 은 이벤트 전체로 재므로 +3 이 만든 변화다.
**게인이 3배로 부풀려진다.** 앵커 2분이면 발생 확률이 크게 줄지만 0 은 아니라,
로그에 반드시 표시해야 한다.

## 요구사항

1. 한 번의 제어 조작은 2분 안에 끝난다는 가정을 **코드가 강제**한다 — 모든 묶음의
   span ≤ 2분.
2. 이벤트 앞뒤 10분 안에 다른 조정이 없으면 그 이벤트는 쓸 수 있다. 판정은 **Wet 을
   보지 않고** 이벤트 시각만으로 한다.
3. 파이프라인 전체에서 "쓸 수 있는 이벤트" 정의는 **하나뿐이어야** 한다.
4. 전처리의 각 단계를 사람이 **혼자 실행하고 혼자 판정**할 수 있는 로그로 낸다.
   (Claude 는 실데이터를 볼 수 없다 — `CLAUDE.md`)
5. 로그의 모든 줄은 원시 데이터로 **손검증 가능**해야 한다.

## 비목표

- 정착 판정(`annotate_settling`) 자체를 지우는 것. 튜닝 종료 교차검증에는 계속 쓴다.
  **선별에서만** 손을 뗀다.
- 10분이라는 값이 옳은지 증명하는 것. 이건 가정이고, 로그가 매 실행마다 스스로
  검사하도록 만드는 것까지가 이 문서의 범위다.
- HTML/그래프 산출물. 텍스트여야 사용자가 몇 줄 잘라 돌려줄 수 있다.

## 설계 1 — 새 전처리 규칙

### 앵커 병합

아직 어느 묶음에도 안 든 가장 이른 변경을 앵커 t₀ 로 삼고, `[t₀, t₀ + merge_minutes]`
안의 변경만 그 묶음에 넣는다. 다음 미배정 변경이 새 앵커가 된다. lot 을 넘지 않는다.

- **모든 묶음의 span ≤ merge_minutes 가 보장된다.** 이게 연쇄 병합과의 유일하지만
  결정적인 차이다.
- 같은 시각의 여러 항목은 당연히 한 묶음이다(기존 성질 유지).

### run_id — 연속 조작 구간의 표식

앵커 창을 넘겨서도 변경이 끊기지 않으면(직전 변경과 `merge_minutes` 이내) 그때 생기는
조각들은 **공통 `run_id`** 를 갖는다. 배제하지 않는다 — 배제는 오직 격리가 한다.
`run_id` 는 로그에서 그 조각들이 한 덩어리였음을 보여주는 용도이고, "전체 변경의 N%가
연속 조작 구간 안" 이라는 통계를 준다.

`run_id` 는 **모든 이벤트에 붙는다.** 다만 run 이 이벤트 하나짜리면(= 쪼개진 적이 없으면)
원장에 `-` 로 찍는다 — 눈에 띄어야 할 것은 쪼개진 것뿐이다.

`run_id` 의 정의는 정확히 **현재 규칙의 연쇄 묶음**이다. 즉 새 코드는 두 층위를 동시에
계산한다: 연쇄(run) 안에 앵커 묶음(event)이 들어 있다. 구/신 대조가 공짜로 나온다.

### 격리 — 끝 기준, ±10분

```
앞간격 = 이 묶음의 첫 변경 − 직전 묶음의 마지막 변경
뒤간격 = 다음 묶음의 첫 변경 − 이 묶음의 마지막 변경
isolated = 앞간격 ≥ pre AND 뒤간격 ≥ post
```

lot 경계는 벽으로 유지한다(`bounds` 를 주면 lot start/end 가 없는 이웃을 대신한다).
이웃도 경계도 없으면 제약 없음(기존 동작 유지).

### 선별 통일

`annotate_settling` / `CONTAMINATED` 는 선별에서 빠진다.

- `features.delta_samples` 는 격리 통과 이벤트를 받는다.
- ΔWet = `mean[t₁ + post − w, t₁ + post] − mean[t₀ − w, t₀)`.
  여기서 t₀ = 묶음의 첫 변경, t₁ = 묶음의 마지막 변경, `post` = 응답창(10),
  `w` = **신설 설정 `coating_delta_window_minutes`(기본 3)**.
  뒤 창은 **보장된 조용 구간의 맨 끝 w분**이다. `SETTLED_AT` 에 의존하지 않으므로
  순환이 완전히 끊긴다.
  기존 `coating_settle_window_minutes`(5) 를 재사용하지 않는 이유: 그 값은
  `annotate_settling` 의 이동창 폭이고 계속 그 용도로 남는다. 뜻이 다른 두 창에 같은
  설정을 쓰면 한쪽을 조정할 때 다른 쪽이 조용히 따라 움직인다.
- `response.align_events` 의 `CONTAMINATED` 필터 제거.

### 설정 변경

| 설정 | 지금 | 새 값 | 근거 |
|---|---|---|---|
| `coating_event_merge_minutes` | 2 | 2 | 유지(의미가 바뀜: 연쇄 → 앵커 span 상한) |
| `coating_isolation_pre_minutes` | 30 | 10 | 대칭 |
| `coating_isolation_post_minutes` | 60 | 10 | 제안 |
| `coating_response_post_minutes` | 60 | 10 | **뒤 격리 = 응답창** 불변식 |
| `coating_response_pre_minutes` | 15 | 10 | 곡선 앞 구간이 보장된 조용 구간을 넘으면 안 됨 |
| `coating_settle_max_wait_minutes` | 30 | 10 | 10분 넘겨 기다리면 다음 이벤트 영역을 본다 |
| `coating_delta_window_minutes` | (없음) | 3 | **신설.** ΔWet 앞뒤 평균창. 10분 창 안에서 앞뒤가 겹치지 않아야 한다 |
| `coating_settle_window_minutes` | 5 | 5 | 유지 — `annotate_settling` 전용으로 뜻이 좁아진다 |

파생값:

- `tau_guess = response_post/2` : 30 → 5
- `isolation_table` windows: `(10,20,30,45,60)` → `(5,10,15,20,30)` — 새 기준이 표
  한가운데 와야 사람이 고를 수 있다.
- `noise_floor` 가드: ±60 → ±10. 조용 구간이 크게 늘어 σ 가 달라진다.
  노이즈 플로어 문서의 결론을 새 σ 로 재확인해야 한다.

`.env.example` 에 같은 값을 넣어 "무엇을 설정할 수 있는지" 문서 역할을 유지한다.

## 설계 2 — 전처리 로그 다섯 층

> 아래 출력 예시의 **숫자는 전부 형식을 보이기 위한 가짜다.** 실데이터를 본 적이 없다.
> 고정된 것은 열 구성과 문장 형식이지 값이 아니다.

### 층 0 — 깔때기: 행이 어디서 죽었나

```
## 0. 어디서 얼마나 줄었나
   원본 행                       1,284,330
   → 분 중복 접기                  412,880   (-871,450)
   → 값이 바뀐 시점만                18,442   (-394,438)
   → 제어 항목만                     1,207   (-17,235)
   → 시작값(lot 첫 관측) 제외         1,178   (-29 = lot 29개)
   ──────────────────────────────────────
   → 2분 앵커 묶음                     214 묶음  (평균 5.5 변경/묶음)
        연속 조작 구간에서 나온 조각      96 (45%)
   → 격리 ±10분 통과                    31 묶음  (14%)
        탈락  앞 62 · 뒤 71 · 양쪽 44 · lot 경계 6
```

**이름 없는 감소가 없어야 한다.** 96%가 한 줄에서 사라져도 그 줄 이름이 "값이 바뀐
시점만" 이면 놀랄 일이 아니다.

### 층 1 — 묶음 원장

```
## 2. 묶음 원장  (214건 중 앞 20 · 전체는 12_event_ledger.csv)
event    lot  run   첫 변경          마지막   span  n  중복  앞간격  뒤간격  zone        판정
L1#001   L1   r01   01-31 19:04:00  19:05:00  1.0  3   -    (첫)    1.5   z3,z7,z12   ✗ 뒤 1.5<10
L1#002   L1   r01   01-31 19:06:30  19:08:00  1.5  2   -     1.5    2.0   z3,z4       ✗ 앞뒤
L1#003   L1   r01   01-31 19:10:00  19:10:00  0.0  1   -     2.0   84.0   z9          ✗ 앞 2.0<10
L1#004   L1    -    01-31 20:34:00  20:35:00  1.0  4   -    84.0   12.0   z1,z2,z5+1  ✓
L1#005   L1    -    01-31 20:47:00  20:47:30  0.5  2  ⚠2    12.0   31.0   z3,z8       ✓ zone3 2회
```

- `run` 열이 앞 세 줄이 원래 한 덩어리였음을 말한다.
- `중복` 열이 문제 4의 Δgap 버그를 드러낸다.
- 판정은 **"무엇이 얼마나 모자랐나"** 로 적는다(`뒤 1.5<10`). 창을 몇으로 바꾸면
  살아나는지가 그 줄에서 바로 읽힌다.
- `zone` 열은 터미널에서 3개까지 + `+N`, CSV 에는 전부.
- 원시 타임스탬프를 실어서 `01_changes_control.csv` 와 손으로 대조할 수 있다.

### 층 2 — 타임라인 스트립

```
## 3. 타임라인  (· 변경  [✓]/[✗] 묶음과 격리 판정  1칸 = 5분)
L1  19:00 ├──[✗][✗]─[✗]──────────────────[✓]──────[✓]────────┤ 23:40
               └─ r01: 6분에 6번 ─┘
L2  06:10 ├─[✓]───────────[✗✗]─────────────────[✓]───────┤ 10:20
```

**모든 lot 을 보여준다.** 통과 이벤트가 하나도 없는 lot 이야말로 봐야 할 것이다.
lot 이 29개면 29줄 + run 주석줄.

**스케일은 lot 마다가 아니라 전체 공통이다.** 가장 긴 lot 이 100칸에 들어가도록
분/칸을 정하고 모든 lot 에 같은 값을 쓴다. 그래야 짧은 lot 이 짧게 그려져 길이가
비교된다 — lot 마다 늘려 맞추면 모든 lot 이 같은 길이로 보여 정보가 사라진다.
"1칸 = N분" 은 헤더에 한 번만 적는다.

### 층 3 — 구/신 규칙 대조

```
## 4. 구 규칙(연쇄·앞30/뒤60) 대비
                    구     신
   묶음             96    214
   격리 통과        11     31
   Δgap 항목        58    104

   양쪽 통과   8건  · 신에만 23건 · 구에만 3건
   구에만 남은 것 = 연쇄가 삼켰던 긴 구간:
     L3#7  구 = 19:04~19:12 한 건(6항목)  /  신 = 조각 4개 전부 탈락
```

여기서 **"구 규칙" 은 세 가지를 다 되돌린 것**이다 — 연쇄 병합 + 시작 기준 간격 +
앞30/뒤60. 하나만 되돌리면 무엇이 차이를 만들었는지 갈리지 않는다.

마지막 줄이 핵심이다 — 구 규칙이 무엇을 **만들어내고 있었는지**가 사례로 나온다.
`run_id` 가 곧 구 규칙의 묶음이므로 묶음 계산은 추가 비용이 없다(격리만 옛 파라미터로
한 번 더 돌린다). 전환 뒤에도 남긴다 — 설정을 다시 만질 때마다 같은 질문을 하게 된다.

### 층 4 — 자기반증: 10분 가정이 아직 서 있나

```
## 5. 10분 창이 반응을 담고 있나
   정렬 응답 곡선 최댓값 lag = +9분   ⚠  마지막 칸이다 — 창이 짧다.
   (+3~+7 근처면 정상. 마지막 lag 이면 창을 늘려야 한다.)
```

10분은 실측이 아니라 가정이다(실데이터 L·τ 는 아직 미지수). 이 두 줄이 매 실행마다
그 가정을 스스로 검사한다. 경고가 뜨면 `COATING_*_MINUTES` 를 올리고 다시 돌린다.

(기존 문서와 손버릇이 깨지지 않게). 기존 3절(격리 표 / 간격 분포 / 병합 민감도)은
새 다섯 절 뒤에 유지한다 — 창을 고르는 근거는 여전히 그 표들이다.

## 테스트

새로 쓰는 것:

- 앵커가 span 을 2분으로 자른다 — `[0, 1.5, 3, 4.5]` → 2묶음, 각 span ≤ 2.
- 연쇄가 더 이상 일어나지 않는다 — `[0, 1.5, 3, 4.5, 6, 8]` → 3묶음 (연쇄면 1묶음).
- 같은 `run_id` 가 조각들에 붙는다.
- 격리 간격이 끝 기준이다 — span 있는 이벤트에서 `gap_after` 가 span 만큼 줄어든다.
- `delta_samples` 가 격리로 고른다 (`CONTAMINATED` 열이 있어도 무시).
- 한 묶음 안 같은 zone 중복이 원장의 `중복` 열에 잡힌다.
- 원장의 판정 사유 문자열이 부족분을 담는다 (`뒤 1.5<10`).

**전제가 뒤집혀 다시 써야 하는 것:**

- `test_merge_sensitivity_shows_data_lost_to_a_narrow_window` — 연쇄 동작(`merge=6` 에서
  `[0,5,10]` 이 한 묶음)을 명시적으로 검증하고 있다. 앵커에서는 `{0,5}`, `{10}` 으로
  갈린다. 이 테스트가 주장하던 "넓히면 살아난다" 는 여전히 참이지만 숫자가 다르다.
- `test_isolation_measures_gaps_to_the_neighbours` — 시작 기준 간격을 검증한다.
  span 이 0인 입력이라 값은 같지만, 의미가 바뀌므로 끝 기준 케이스를 추가한다.

검증은 `tests/fixtures/` 의 합성 데이터로 한다. 실데이터는 사용자가 돌린다.

## 사용자에게 넘길 것

전환 후 사용자가 사내 PC 에서 실행할 명령과, 출력을 읽는 분기표를 함께 낸다.

```
python -m app.coating.diagnose --preprocess data/coating/raw/merged.parquet
```

돌려줄 것은 **§0 깔때기와 §4 대조표, §5 자기반증 세 덩어리**뿐이다.
원본 데이터는 요청하지 않는다.

분기표(초안):

| §5 가 말하는 것 | 뜻 | 다음 |
|---|---|---|
| 최댓값 lag 이 +3~+7 | 10분 창이 반응을 담고 있다 | 그대로 진행 |
| 최댓값 lag = 마지막 칸 | 창이 짧다 | `POST`/`RESPONSE_POST` 를 20으로 올리고 재실행 |
| 곡선이 σ 아래 | 반응이 노이즈에 묻혔다 | 표본 부족 — §0 의 통과 건수를 본다 |

| §0 격리 통과 건수 | 뜻 | 다음 |
|---|---|---|
| ≥ 20건 | 커널 추정 하한(`_MIN_EVENTS`)을 넘는다 | 진행 |
| 5~19건 | L·τ 는 볼 수 있으나 커널은 이르다 | 창을 좁혀(±5) 재시도 후 §4 로 손실 확인 |
| < 5건 | 이 데이터로는 안 된다 | §4 의 "구에만" 건수를 근거로 사업부에 요구 |

## 결정과 근거

**뒤 격리 10분 = 응답창 10분.** 뒤 격리가 10분인데 응답을 60분 읽으면, 그 60분 중
50분은 다른 조정이 섞여 있어도 통과한다. 그건 이 이벤트의 응답이 아니다. 둘을 같은 수로
묶는 불변식을 세웠다. **이는 "반응이 10분 안에 끝난다" 는 검증되지 않은 주장 위에 서 있다**
— 실데이터 L·τ 는 아직 미지수다. 그래서 층 4(자기반증)를 필수로 넣었다.

**선별은 격리로 통일.** 정착 판정은 L 을 알아야 제대로 서는데 L 을 여기서 잰다(순환).
게다가 창이 10분으로 줄면 `_settle_time` 이 5분 이동창으로 판정할 수 있는 자리가
+5~+10분 여섯 칸뿐이라 기계 자체가 무력해진다. 격리는 이벤트 시각만 보므로 그 고리 밖에 있다.

**연속 조작은 쪼개되 `run_id` 를 단다.** 구간 통째 배제도 검토했으나, 그러면 격리 말고
두 번째 배제 규칙이 생겨 "선별 정의는 하나" 라는 방금의 결정과 충돌한다. `run_id` 는
배제하지 않고 **설명만** 한다 — 로그의 가독성은 얻고 규칙은 하나로 남는다.

**로그는 텍스트.** 사용자가 몇 줄 잘라 붙여넣을 수 있어야 왕복이 성립한다. HTML 은
보기엔 좋지만 돌려줄 수가 없다.
