# 코팅 초기조건 도출 설계

- 날짜: 2026-08-25
- 배경: 양산 라인의 코터 설비는 job change 이후 코팅 로딩레벨(L/L)을 목표값에 맞춰야 한다.
  지금은 작업자가 L/L 을 보면서 제어값을 손으로 조절한다. 최적값을 빨리 못 찾으면 그동안
  흘러간 기재를 버려야 하고, 그게 곧 로스다. 이 문서는 그 초기 조건을 **데이터로 도출하는**
  파이프라인과 모델을 설계한다.
- 선행 문서: 없음 (신규 과제). 기존 채팅·금형 대시보드와 독립적인 세 번째 기능이다.
- 결정 경위: 6라운드 grilling 세션으로 설계 트리를 닫았다. 각 결정의 근거는 마지막 절에 남긴다.

## 요구사항

1. Job change 직후 **A면** 코팅 L/L 을 목표값에 맞추는 초기 제어값을 도출한다.
2. 사업부가 제공한 CSV 를 그대로 입력으로 쓴다. 양식은 정형이며 바뀌지 않는다.
3. 지금 가진 데이터가 **최적화 가능한 데이터인지 먼저 판정**한다. 판정 없이 모델을 짓지 않는다.
4. 학습한 모델을 **검증할 수 있어야** 한다. 오프라인 검증이 우선이고, 파일럿은 추후 가능하다.

## 목표

- 원본 CSV 에서 **조정 이벤트**(사람이 제어값을 바꾼 순간)를 빠짐없이 복원한다.
- 제어값 → L/L 관계를 학습하고, 목표 L/L 을 만족하는 제어값을 **역산**한다.
- 모델이 **나이브 베이스라인을 이기는지**를 숫자로 보인다. 못 이기면 그 사실을 보고한다.
- 데이터가 학습에 부족하면 **무엇이 얼마나 부족한지**를 사업부에 전달할 수 있는 형태로 낸다.

## 비목표

- **LLM / AI Agent 를 쓰지 않는다.** 수치 정밀도가 필요한 회귀에 언어모델을 쓸 이유가 없고,
  CSV 가 정형이라 파싱에도 에이전트가 필요 없다. 기존 `app/ingest` 의 ReAct 파이프라인은
  이 과제에서 재사용하지 않는다.
- **신경망을 쓰지 않는다.** 수백~수천 행 규모의 정형 테이블이다. 이 구간에서 신경망이
  트리 앙상블이나 선형 모델을 이기지 못한다.
- B면 제어 (A면만 다룬다)
- 보정 루프 = 실측 L/L 을 보고 다음 조정을 제안하는 순차 의사결정 (v2).
  단, **거기에 쓸 델타 샘플 테이블은 v1 에서 미리 만들어 둔다.**
- 앱 UI 통합 (v2)
- 설비에 값을 직접 쓰는 것. v1 은 **recommend-only** 다.

## 데이터

### 원본 형태

단일 CSV, long(EAV) 포맷이다.

| 컬럼 | 예시 |
|---|---|
| Lot ID | `GRQC48XP29` |
| 작업일 | `2026-01-31 18:55` (분 단위) |
| 제품 약칭 | `BNB48X1` |
| 항목 ID | `30030843` |
| 항목명 | (대부분 비어 있음 — 사전으로 조인한다) |
| Value | `315` |

**핵심 성질 세 가지.** 이걸 놓치면 전처리가 통째로 틀린다.

1. **모든 항목 ID 가 각 시점마다 여러 번 찍힌다.** 주기적 스냅샷 로깅이다.
2. **값은 계단형이다.** lot 시작 시 모든 항목에 시작값이 존재하고, 사람이 바꾼 순간부터
   새 값이 계속 반복 기록된다. (예: T_Block 6zone 이 x 였다가 특정 시점부터 x+1)
3. 따라서 전처리의 본체는 **항목별 변경 시점 추출(run-length 압축)** 이다.

이 성질 덕분에 **작업자의 튜닝 과정 하나하나가 자연 발생한 계단 응답 실험**이 된다.
일반 교차상관으로 lag 을 뭉뚱그려 추정할 필요가 없다 — 각 이벤트의 계단 응답에서
lag(반응 시작까지)과 gain(최종 변화량)이 함께 나온다. 영향행렬은 그 gain 들의 모음이다.

### 항목 구성

| 구분 | 항목 | 개수 |
|---|---|---|
| 제어 | BP value open rate, Pump RPM, OS Gap, DS Gap | 4 |
| 제어 | **T_Block UNIT Gap Offset 1~25 Zone** | 25 |
| 상태(L/L) | **GV UNIT Wet 1~25 Zone** | 25 |

**즉 29 입력 → 25 출력의 폭방향(cross-direction) 프로파일 제어 문제다.**
"다이 갭 조절"의 실체는 폭방향 25개 zone 의 다이 볼트 오프셋이다.

항목 사전은 `backend/data/coating/meta/item_dictionary.csv` 에 있다
(`item_id, item_name, io, role, zone`). 샘플 데이터의 모든 항목 ID 가 여기 매칭된다.

### 목표값과 합격 판정

- 48X1 목표: **18.23 ± 0.4 mg/cm²**
- 합격: **모든 유효 zone 이 각각 스펙 내** (AND 조건).
  평균만 보면 한쪽이 두껍고 반대쪽이 얇은 최악의 프로파일이 통과해버린다.
- 폭방향 σ 는 판정에 쓰지 않고 **제2 지표로 병기**한다. 레벨 문제와 균일도 문제를
  분리해서 보기 위해서다.

### 관측된 사실 (샘플 31행 프로파일링)

- 항목 사전 매칭률 100%.
- **Wet 관측 산포가 스펙의 6.3%** — 범위 18.21~18.26(폭 0.050) vs 스펙폭 0.8.
  이 구간은 이미 완전히 안정된 구간이다.
- **9분 동안 제어값이 하나도 안 변했다** (관측 입력 14개 중 변경 0개).
- 레벨을 지배하는 `BP value open rate` 와 `Pump RPM` 이 샘플에 없다.
- `Wet = 0` 은 zone 18 하나. 그런데 그 zone 의 gap offset 은 210 으로 정상값이다.
- 출력과 입력의 로깅 시각대가 다르다 (출력 18:55~18:56 / 입력 18:56~19:04).

## 문제 정식화

### level / profile 분해

`Wet_i = L + p_i` 로 나눈다.

| | 대상 | 지배 변수 |
|---|---|---|
| **L** (전체 레벨) | zone 평균 | Pump RPM, BP open rate, OS/DS Gap, 제품 |
| **p** (프로파일) | 평균 대비 편차 | T_Block zone offset |

물리적으로 두 메커니즘이 다르다. 총 토출량이 레벨을 정하고, zone 별 갭이 그 레벨을
폭방향으로 재분배한다. 분해하면 (1) 프로파일 파트가 거의 선형이 되고, (2) 25개 출력을
각각 배우는 대신 **영향행렬 하나를 공유**해 파라미터가 급감하며, (3) 현장 용어와 맞는다.

사내에 코팅 물리식도 작업자 경험칙도 없다고 확인됐다.
**따라서 이 분해 구조 자체가 우리가 주입할 수 있는 유일한 물리 지식이다.**

### 영향행렬 G 의 구조

`Δwet = G · Δgap` 에서 G 는 25×25 다. **Toeplitz(공간 불변) + 밴드**로 제약한다.

| 구조 | 파라미터 | 이벤트당 방정식 | 필요 이벤트(견고하게) |
|---|---|---|---|
| **Toeplitz + 밴드 k=2** | **5** | 25 | **20~50** |
| 밴드 k=2 (zone별 자유) | ~117 | 25 | ~300 |
| 자유 25×25 | 625 | 25 | 1,000+ |

다이 볼트 하나를 조이면 주변으로 종 모양으로 퍼지고, 그 퍼짐 모양은 zone 위치와
거의 무관하다. Toeplitz 는 수학적 편의가 아니라 실제 물리를 반영한다.

**진짜 제약은 개수가 아니라 랭크다.** 작업자가 늘 비슷한 패턴으로 조정하면 lot 이 많아도
Δgap 행렬의 유효 랭크가 3~4 에 그친다. 이건 특이값 분해로 숫자 하나로 측정되며,
**리포트의 필수 항목**이다.

### 역산 — surrogate + 탐색

`g(조건, 목표) → 제어값` 을 직접 회귀하지 **않는다**. 같은 L/L 을 만드는 (갭, GV, RPM)
조합이 무수히 많아 역이 유일하지 않고, 직접 회귀하면 모델이 여러 정답의 **평균**을
뱉는데 그 평균 조합은 어느 것도 아닌 값일 수 있다.

대신 surrogate `f(제어) → Wet` 를 학습하고 제어 공간을 탐색한다. 실현 가능한 해집합을
전부 보고 그중에서 추가 기준으로 하나를 고를 수 있다.

- 목적함수: **목표오차 + 폭방향 균일도 + 현재 설정값 대비 이동거리**(정규화 항)
- 제약: zone 별 gap 상하한, **인접 zone 간 급단차 금지**
- 출력: 점추정 + **부트스트랩 예측구간** + **경험범위 밖 경고 플래그**

이동거리 항이 실무적으로 결정적이다. 수학적으로 동등한 해가 여럿일 때 작업자가 지금
값에서 가장 적게 움직여 도달할 수 있는 해를 골라줘야 실제로 쓴다.
**25개 볼트를 전부 새 값으로 바꾸라는 제안은 아무도 따르지 않는다.**

## 전처리 파이프라인

```
long CSV (분 단위, 항목별 중복 다수)
 → 항목사전 조인 (item_id → 이름/io/zone)
 → 분 단위 중복 해소: 제어·출력 모두 마지막 값
 → 항목별 run-length 압축 → (변경시각, 새 값) 시퀀스
 → forward-fill 로 임의 시각의 전체 상태 벡터 복원
 → Lot ID 로 그룹화, 초기 구간 절단
     1차: gap 마지막 변경 시점까지
     교차검증: 목표±0.1 안정 진입 시점까지
 → 조정 이벤트 생성: T분(1~2분) 이내 변경들을 하나의 Δgap 벡터로 묶음
 → 이벤트별 계단 응답에서 lag · 정착시간 추정
     안정화 판정: Wet 이동 표준편차 < 임계
     ⚠ 재안정 전 다음 변경이 온 이벤트는 오염으로 제외
 → 샘플 테이블 2종
     절대: (안정구간 제어벡터 → 안정구간 Wet 25)   — 1샷용
     델타: (Δgap 벡터 → ΔWet 25)                 — 영향행렬 · v2 보정용
```

단계마다 parquet 을 적재한다(`raw/ → interim/ → features/`). 이 과제는 "왜 이 숫자가
이렇게 나왔지"를 반드시 되짚게 되고, 중간 산출물이 없으면 되짚을 수 없다.

**설계 판단 세 가지.**

- **초기 구간 정의는 두 가지를 다 계산한다.** 스펙 ±0.4 는 합격 판정용이지 튜닝 종료
  판정용으로는 너무 헐겁다 — 실제 변동이 ±0.03 이면 Wet 은 job change 직후 사실상 즉시
  스펙에 들어와 구간 길이가 0 에 수렴한다. 1차 기준은 "사람이 손 뗀 시점"(gap 마지막 변경)
  이고, "목표±0.1 안정 진입"은 교차검증용이다. 두 시점이 크게 어긋나면 그 차이 자체가
  발견이다 — 스펙보다 엄한 암묵적 기준이 존재한다는 증거이고, 그게 진짜 목표값이다.
- **오염 이벤트를 반드시 배제한다.** 재안정 전에 다음 변경이 오면 두 변경의 효과가 겹쳐
  인과를 분리할 수 없다. 그대로 넣으면 영향행렬이 조용히 망가진다. 제외 비율도 리포트에
  넣는다 — 그 비율이 높으면 "튜닝이 급하게 이뤄진다"는 현장 진단이 된다.
- **동시 변경은 하나의 이벤트로 묶는다.** 항목별로 쪼개면 하나의 Wet 변화가 여러 이벤트에
  중복 귀속되어 각 zone 의 영향이 부풀려진다. 애초에 배우려는 것이 벡터 관계다.

## 모델

| | 모델 |
|---|---|
| **L** (레벨) | **릿지 + 제품 고정효과를 베이스라인**. HistGradientBoosting 이 유의미하게 못 이기면 릿지 채택 |
| **p** (프로파일) | `Δwet = G·Δgap`, **G 는 Toeplitz + 밴드**, k 는 교차검증, 양 끝 zone 은 zero-pad |

레벨 모델에 트리 앙상블을 먼저 쓰지 않는 이유: 이 문제는 물리적으로 단조롭고(토출량↑ ⇒
로딩↑) 변수가 몇 개 안 된다. 그런 문제에 트리를 쓰면 구간별로 계단처럼 튀는 예측이
나오고, 그게 역산 최적화 단계에서 이상한 해를 만든다.

## 검증

- **분할**: lot 단위 GroupKFold + 시간순 홀드아웃 **둘 다**.
  둘의 차이가 크면 드리프트(슬러리 배치 변화, 다이 마모)가 있다는 뜻이고,
  그게 재학습 주기를 정하는 근거다.
- **지표**: 레벨 MAE, 프로파일 RMSE, 폭방향 σ, **첫 시도 스펙 hit rate**
- **"예측 정확도"와 "제안 품질"을 분리**한다. 후자는 "과거 lot 에서 사람이 최종 도달한
  조건 vs 모델 제안"의 거리, 그리고 "모델 제안을 surrogate 에 넣었을 때 스펙 내인가"다.
- **반드시 이겨야 할 나이브 베이스라인 2개**
  1. 직전 동일 제품 lot 의 최종 조건 재사용
  2. 동일 제품 과거 lot 최종 조건 중앙값

  **못 이기면 이 과제의 정답은 모델이 아니라 "제품별 최종조건 표준 테이블"이다.**
  그것도 유효한 결론으로 보고한다 — 훨씬 싸게 로스를 줄인다. 이 베이스라인 없이 모델
  MAE 만 보고하면 "좋아 보이는데 실제로는 아무것도 개선 못 하는" 결과를 못 알아챈다.
- **물리 정합성 검사**(단조성) 통과가 필수다. 통계적으로 잘 맞으면서 물리적으로 말이 안 되는
  모델은 현장에서 신뢰를 한 번에 잃는다.
- 이후 현장 shadow → 파일럿 순으로 확장한다.

## 산출물 (v1 = 마일스톤 a+b)

재현 가능한 스크립트 + **Markdown 리포트(리뷰·diff 용)** + **HTML 리포트(사업부 전달용)**.

리포트 필수 항목:
- lot 수 · 기간
- **lot 당 gap 변경 횟수 분포** ← 학습 가능성의 1차 관문
- **Δgap 행렬 특이값 스펙트럼(유효 랭크)** ← 2차 관문
- 계단 응답 lag 분포
- 오염 이벤트 비율
- zone 별 프로파일
- 베이스라인 대비 성능
- **사업부 추가 데이터 요청 목록**

| 가정 | 틀렸을 때 |
|---|---|
| lot > 100 | 미달 시 Toeplitz 보다 강한 제약(커널 폭 1~2 파라미터)으로 후퇴 |
| `Wet=0` = 미사용 zone → 영구 NaN 마스킹 | 센서 이상이면 해당 lot 만 제외 |
| 유효 폭은 제품별 고정 | lot 마다 다르면 lot 별 마스크 |
| RPM · BP open rate 정상 로깅 | 없으면 레벨 모델은 제품상수 + OS/DS Gap only → **정확도 기대치 대폭 하향, 리포트에 명시** |
| SV 항목 없음 → PV 를 그대로 사용 | SV 존재 시 SV↔PV 오프셋 확인 후 출력 형태 변경 |
| Δgap 랭크 충분 | 부족하면 **강한 제약으로 후퇴 + 파일럿 DOE 제안** |

**네 번째 가정이 가장 위험하다.** RPM 과 BP open rate 는 레벨 모델의 핵심 변수인데
샘플에 없었다.

### 식별에 실패하면

Δgap 랭크가 낮게 나오는 건 실패가 아니라 예상 가능한 결과다. 미리 정해둔다.

1. **더 강한 제약으로 후퇴** — 커널을 파라미터 1~2개짜리 모양(예: 가우시안 폭 하나)으로 고정
2. **동시에 파일럿 DOE 를 제안** — 의도적으로 다양한 Δgap 패턴을 넣어 랭크를 채운다

"데이터로는 불가"라고 멈추지 않는다. 그리고 (2)가 이 과제의 가장 큰 장기 가치일 수 있다.
**"기존 데이터로 모델을 만든다"보다 "모델을 만들 수 있는 데이터를 만들기 시작한다"가
더 중요한 결론일 가능성이 상당하다.**

## 결정 이력

grilling 6라운드에서 확정된 것 중, 나중에 "왜 이렇게 했지"가 나올 만한 것만 남긴다.

| 결정 | 왜 |
|---|---|
| Agent 대신 ML | CSV 가 정형이고 수치 회귀에 언어모델이 필요 없다 |
| level/profile 분해 | 두 메커니즘이 물리적으로 다르고, 분해가 유일하게 주입 가능한 물리 지식이다 |
| Toeplitz 영향행렬 | 파라미터 625 → 5. 데이터 규모가 아니라 랭크가 제약이므로 보수적 선택이 아니라 유일한 안전 선택 |
| surrogate + 탐색 (직접 역회귀 아님) | 역이 유일하지 않아 직접 회귀는 정답들의 평균을 뱉는다 |
| 목적함수에 이동거리 항 | 없으면 25개 볼트를 다 바꾸라는 제안이 나오고 현장에서 안 쓴다 |
| 초기 구간을 두 정의로 계산 | 스펙 ±0.4 가 튜닝 종료 판정에는 너무 헐겁다(실제 변동 ±0.03) |
| 오염 이벤트 배제 | 겹친 변경은 인과 분리가 불가능하고 영향행렬을 조용히 망가뜨린다 |
| 나이브 베이스라인 2종 필수 | 못 이기면 정답이 "모델"이 아니라 "표준 조건 테이블"이다 |
| 분 단위 중복은 마지막 값 | 값이 계단형 유지값이다. 안정 구간이 여러 분에 걸쳐 있어 노이즈 감소는 구간 평균에서 회수된다 |
