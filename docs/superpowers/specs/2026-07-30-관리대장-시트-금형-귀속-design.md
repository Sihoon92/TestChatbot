# 관리대장의 금형 귀속을 시트 이름으로 바꾼다

**작성일** 2026-07-30
**상태** 설계 승인. 구현 전.
**범위** 관리대장(EES) 의 금형 귀속 규칙과 레이아웃 캐시 키. MES/IQC/PQC 의
귀속 방식과 대시보드 화면은 건드리지 않는다(손실 표시 한 줄 제외).

## 왜 고치는가

`2026-07-29-ees-mes-조인-design.md` 와 그 구현(`ba389b1`)은 관리대장을
**"한 시트에 여러 금형이 시간순으로 섞여 있고, 행마다 있는 JIG ID 열이 그 행의
금형을 확정한다"** 고 전제했다.

**전제가 틀렸다.** 실물 관리대장은 다음과 같다.

- **시트 하나 = 금형 하나**
- **시트 이름이 그 금형의 JIG ID** (`#RX39513` 꼴, 부가 텍스트 없음)
- **시트 안에 JIG ID 열이 없다**
- 파일 안의 모든 시트가 금형 시트다 (표지·목차·집계 시트 없음)
- 시트 수는 10개 미만

이 전제는 검증 없이 세워졌고, 코드 주석·커밋 메시지·**LLM 발견 프롬프트**에
사실로 기록됐다. 현재 코드에 실물을 넣으면 모든 행이 `mold_no` 를 얻지 못해
**금형 0건**이 나온다.

## 규칙

> **관리대장에서 금형을 확정하는 것은 워크북의 실제 시트 이름이다.**
> 시트 안의 어떤 열도 금형을 확정하지 않는다.

`normalize_mold_no` 가 `#` 접두사와 대소문자를 이미 처리하므로 시트 이름을
그대로 통과시킨다 (`#RX39513` → `RX39513`).

JIG ID 열 경로는 **지원하지 않는다.** 열이 있어도 무시한다. 규칙이 둘이면
둘이 어긋났을 때 무엇이 옳은지 정할 근거가 없다.

## 귀속 규칙은 어느 계층에 사는가

`parser.py` 의 첫머리에 이미 원칙이 선언돼 있다 — *"금형 귀속은 하지 않는다.
IQC 는 금형번호 열로, PQC 는 조인으로 귀속되는데 그 차이가 여기 섞이면 읽을 수
없어진다."* 이번 규칙은 그 목록의 세 번째다.

| 소스 | 귀속 방법 | 사는 곳 |
|---|---|---|
| IQC | 금형번호 **열** | `assemble.py` |
| PQC | (날짜·공정·호기·시간) **조인** | `assemble.py` |
| **EES 관리대장** | **시트 이름** ← 신규 | `join.py` |

파서는 계속 "레이아웃이 지목한 셀을 필드명으로 담은 행"까지만 만든다.
`SheetLayout` 스키마는 바뀌지 않는다 — 레이아웃에 "이 시트의 이름이 곧
mold_no" 라는 선언 필드를 두는 안은 버렸다. 관리대장에서 그 값은 항상 참이라
사실상 상수인 필드가 스키마에 생기고, LLM 이 정하게 하면 틀릴 여지가 새로
생기며, 그 값이 캐시된 레이아웃에 굳어 붙는다.

## 데이터 흐름

```
워크북 ──┬─ 실제 시트명 "#RX39513" ────────────────────┐
         │        (LLM 을 거치지 않는다)                │
         └─ 격자 ─→ [LLM 레이아웃 발견] ─→ 파서 ─→ Row(sheet="#RX39513")
                                                       │
                                     join.extract_runs │ normalize_mold_no(row.sheet)
                                                       ▼
                                                mold_no = "RX39513"
```

## 실제 시트명이 LLM 을 거치지 않아야 하는 이유

현재 `Row.sheet` 는 LLM 이 적어낸 `layout.sheet_name` 이다
(`parser.py:88,115`). 그 값이 금형 정체성이 되면 **LLM 오기가 곧 금형
오귀속**이다.

이건 캐시 변경(아래)의 **전제**이기도 하다. 캐시를 kind 로만 조회하면 시트 A
에서 학습한 레이아웃이 시트 B 에 재사용되는데, 그 레이아웃의 `sheet_name` 은
여전히 `"A"` 다. 고치지 않으면 **모든 금형이 A 하나로 뭉친다.**

따라서 `parse_rows` 는 실제 시트명을 **필수 인자**로 받는다. 기본값
(`layout.sheet_name` 폴백)을 두면 호출부에서 빠뜨렸을 때 이 사고가 조용히
난다. 호출부는 `pipeline.py` 두 곳과 테스트 15곳이며, 테스트 수정은 기계적이다.

같은 이유로 `discover._gaps` 도 실제 시트명을 쓴다. 지금은
`wb.used_values(layout.sheet_name)` 이라 LLM 이 시트명을 잘못 적으면 커버리지
검증이 조용히 건너뛰어진다.

## 코드 변경

| 파일 | 변경 |
|---|---|
| `schemas.py` | `EES_FIELDS` 에서 `mold_no` 제거 (`event_at`·`location`·`equipment`·`line`·`process` 만 남음). 주석의 "한 시트에 여러 금형" 서술 교체 |
| `parser.py` | `parse_rows(..., sheet_name)` 필수 인자 추가. `Row.sheet` 와 오류 메시지가 실제 시트명을 쓴다 |
| `pipeline.py` | 시트 순회 변수를 `parse_rows` 두 호출 지점에 전달 |
| `discover.py` | `FIELD_GUIDE["ees"]` 재작성. `_gaps` 가 실제 시트명 사용 |
| `join.py` | `extract_runs`·`latest_locations` 가 `normalize_mold_no(row.sheet)` 로 귀속. 모듈 docstring 의 조인 다이어그램 수정 |
| `registry.py` | `load_layouts` 의 `sheet_name` 필터 제거. `record_run`/`latest_run` 에 `bad_sheet_names` |
| `db.py` | `ingest_run.bad_sheet_names_json` 컬럼 + `_ADDED_COLUMNS` 항목 |
| `IngestPanel.tsx` | `bad_sheet_names` 표시 한 줄 |

`bad_sheet_names` 는 `RunSummary` 에 실려 DB 에 남으므로 `ingest_run` 에 컬럼이
하나 는다. `CREATE TABLE IF NOT EXISTS` 는 기존 테이블에 컬럼을 붙여주지
않으므로 `SCHEMA` 와 `_ADDED_COLUMNS` **양쪽에** 적는다 — 한쪽만 적으면 예전
`molds.db` 를 쓰던 환경에서 `record_run` 이 "no such column" 으로 터져 배치가
통째로 실패한다. (레이아웃 캐시 쪽 `sheet_mapping` 은 마이그레이션이 없다.)

`SheetLayout` 스키마와 `assemble.py` 의 IQC/PQC 귀속은 무변경이다.

### `FIELD_GUIDE["ees"]` 가 말해야 할 것

현재 프롬프트는 LLM 에게 틀린 사실을 단언하고 없는 열을 찾으라고 압박한다.

- 삭제: *"한 시트에 여러 금형의 사건이 섞여 시간순으로 적혀 있다"*
- 삭제: *"mold_no(JIG ID) 는 반드시 찾아야 한다. 놓치면 파일 전체가 버려진다"*
- 추가: 이 시트는 **금형 하나**의 이력이고, 그 금형은 **시트 이름**이 정한다.
  시트 안에 JIG ID 열은 **없다**. 찾지 마라.
- 필수 필드: `location`, `event_at`

이 "필수"는 프롬프트가 LLM 에게 요구하는 것이지 코드 검증이 아니다.
`_make_submit_tool` 의 제출 검증은 **격자 커버리지**(값이 있는데 매핑 안 된
열·행)만 본다. 특정 필드의 존재를 강제하는 검증은 지금도 없고 새로 넣지 않는다.

## 손실 보고

`rows_without_mold_no` 의 **의미가 바뀐다.** 지금은 "이 행의 JIG ID 칸이
비었다"(행 단위 사고)인데, 앞으로는 "시트 이름이 JIG ID 로 안 읽힌다"(**시트
단위 사고**)다. 시트명 하나가 깨지면 그 시트의 전 행이 한꺼번에 죽는다.

행 수만 세면 *"37행이 빠졌다"* 만 보이고 **어느 시트인지**는 안 보인다. 모든
시트가 금형 시트인 상황에서 이건 사람이 고칠 수 없는 보고다.

두 값을 함께 남긴다.

| 필드 | 의미 | 흐름 |
|---|---|---|
| `rows_without_mold_no` (유지) | 귀속 실패한 행 수 | `assemble.py:192` 에서 `RunSummary.skipped_rows` 에 합산 |
| **`bad_sheet_names`** (신규) | JIG ID 로 안 읽힌 시트 이름 목록(중복 제거) | `JoinLosses` → `RunSummary` → 화면 |

`unknown_jig_id`(시트명은 읽혔는데 기준정보에 없음)와는 다른 사고다. 전자는
"관리대장 시트 이름이 이상하다", 후자는 "기준정보가 낡았다" — 사람이 열어볼
파일이 다르다.

손실 집계는 `extract_runs` 한 곳에서만 한다. `latest_locations` 도 같은 행을
훑지만 거기서 또 세면 같은 시트가 두 번 보고된다.

## 레이아웃 캐시를 kind 로만 조회한다

```sql
-- registry.load_layouts
- WHERE kind = ? AND sheet_name = ?
+ WHERE kind = ?
  ORDER BY id DESC
```

시트 이름이 이제 금형번호라 캐시 키로 쓰기에 부적절해졌다. 시트마다 이름이
달라 양식이 똑같은 시트들이 각각 LLM 발견을 돈다.

`pick_layout` 은 그대로 두고 **앵커 일치가 유일한 판정 기준**이 된다.
`save_layout` 은 계속 `sheet_name` 을 기록한다 — 추적용이지 조회 키가 아니다.
**DB 마이그레이션은 없다.** 기존 행은 그대로 후보가 된다.

효과: 관리대장 시트 N개 → **LLM 발견 1회**. 첫 시트에서 학습한 레이아웃을
나머지가 앵커로 재사용한다. MES(파일마다 한 시트)도 같은 이득을 본다.

**위험**: 같은 kind 안에서 양식이 다른 시트인데 앵커가 우연히 맞으면 잘못
파싱된다. 완화 요소는 후보가 최신순이라 새로 발견한 레이아웃이 먼저
시도된다는 점과, `layout.anchors_match` 가 앵커 3개 미만인 레이아웃을 재사용
후보에서 아예 제외한다는 점이다 — **스키마가 아니라 판정부에서** 강제한다.
`AnchorCheck` 자체에는 개수 제약이 없다: `SheetLayout` 은 `registry.load_layouts`
의 역직렬화도 겸하는데, 스키마에 `min_length` 를 걸면 앵커가 3개 미만으로 이미
저장된 옛 캐시 행을 읽을 때 `ValidationError` 로 레이아웃 로딩 전체가 죽는다.
판정부에서 걸러진 레이아웃은 그냥 캐시 미스로 재발견될 뿐이라 안전하게
퇴화한다.

## 샘플

`make_sample_uploads.py` 의 관리대장을 **시트 = 금형**으로 되돌린다(시트명
`#RX39513` 꼴, JIG ID 열 없음). `61d1fea` 가 만든 케이스 커버리지는 유지한다.

| 시트 | 겨누는 것 |
|---|---|
| `#RX39513` | 수리 왕복 4회 + 정확히 96시간 → 4일 (올림 경계) |
| `#RX28312` | 설비 → 설비 연속 (나가는 기록 없이 재투입) |
| `#RX28315` | 마지막이 수리 → 상태 '수리중' |
| `#RX50177` | 자정 넘김 24h 미만 다수 + 기준정보에 없는 설비명(폴백 경로) |
| `#RX41194` | 마지막이 설비 → 가동 중(종료 없음) |
| `#RX39002` | 마지막이 폐기 |
| `#RX77777` | 기준정보에 없는 JIG ID → 통째로 빠지는 경로 |

시각은 정각으로 둔다 — 96시간 경계가 이 샘플의 핵심 검증 대상인데 분·초를
흩으면 96.5h 가 되어 하루가 더 붙는다.

`bad_sheet_names` 경로는 샘플에 넣지 않는다. 실물에 비금형 시트가 없으므로
샘플은 실물을 닮게 두고, 그 손실 경로는 단위 테스트로 덮는다.

`check_samples.py` 의 기대값도 함께 갱신한다.

**신규**

   `Row.sheet` 가 **B** 인지. 깨지면 전 금형이 한 덩어리가 되므로 가장 중요한
   방어선이다.
2. **`bad_sheet_names`** — 시트명이 JIG ID 로 안 읽히면 목록에 오르고 그
   행들이 `skipped_rows` 로 잡히는지
3. **캐시 재사용** — 같은 양식 시트 N개에 LLM 발견이 1회만 도는지

## 이 변경으로 사라지는 실패 모드

"한 시트에 여러 금형이 섞여 A 의 구간이 B 의 이벤트로 닫힌다" — `ba389b1` 이
고쳤던 버그다. 시트가 곧 금형이면 **구조적으로 발생 불가**가 된다.

`extract_runs` 의 `by_mold` 묶음은 그대로 둔다. 금형 이력이 파일 경계를 넘어
이어지는 것과, 관리대장이 겹쳐 올라올 때 같은 이벤트를 접는 것은 여전히
필요하기 때문이다.
